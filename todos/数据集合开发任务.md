## 3. 集合实现规范

### 3.1 集合分类与更新策略

| 类型 | 特征 | 更新策略 | 示例 |

|------|------|----------|------|

| **无参数**| AKShare 接口无参数 | 仅批量更新（全量刷新） | `futures_fees_info` |

|**单参数-代码**| 需要 symbol/code | 单条+批量（遍历代码列表） | `stock_individual_info_em` |

|**单参数-日期**| 需要 date | 单条+批量（遍历日期范围） | `futures_dce_position_rank` |

|**多参数**| 需要多个参数 | 单条+批量（组合遍历） | `stock_zh_a_hist` |

|**时间序列**| start_date + end_date | 增量更新（从最新日期续取） | `futures_hist_em` |

### 3.2 唯一键设计原则

| 数据类型 | 唯一键组合 | 示例 |

|----------|-----------|------|

| 实时行情快照 | `[代码]` | `stock_zh_a_spot_em` |

| 历史行情 | `[代码, 日期]` | `stock_zh_a_hist` |

| 日度截面 | `[日期, 代码]` 或 `[日期, 排名]` | `futures_dce_position_rank` |

| 季度/年度 | `[代码, 报告期]` | `stock_balance_sheet_by_report_em` |

| 无主键数据 | `[序号]` 或 `[更新时间, 行号]` | 特殊处理 |

### 3.3 批量更新参数来源

| 参数类型 | 数据来源 | 配置方式 |

|----------|----------|----------|

|**股票代码**| `stock_info_a_code_name` 或 `stock_zh_a_spot_em` | `batch_source_collection` |

|**期货品种**| `futures_comm_info` 或交易所合约信息 | `batch_source_collection` |

|**期权合约**| `option_contract_info_ctp` 或交易所列表 | `batch_source_collection` |

|**日期范围**| 数据库最新日期 → 今天 | `batch_use_date=True` |

|**年份范围**| 2010 → 今年 | `batch_years_range=(2010, None)` |

## 5. 并行开发指南

### 5.1 分工方式

可同时在**4 个独立窗口**并行开发，各模块文件路径独立，不会冲突：

| 窗口 | 模块 | 工作目录 |

|------|------|----------|

| 窗口 1 | futures | `app/services/data_sources/futures/` |

| 窗口 2 | options | `app/services/data_sources/options/` |

| 窗口 3 | stocks (前半) | `app/services/data_sources/stocks/` |

| 窗口 4 | stocks (后半) | `app/services/data_sources/stocks/` |

>**注意**：修改 `collection_metadata.py` 或 `{module}_update_config.py` 时需协调，避免同时编辑。

### 5.2 开发流程（单个集合）

```bash

1. 查阅 AKShare 接口文档 → 确定参数、返回字段、唯一键
2. 创建 Provider 文件 → 定义 collection_name, akshare_func, unique_keys, field_info
3. 创建 Service 文件 → 定义 provider_class, 批量更新配置（如需）
4. 重启后端 → 验证自动注册
5. 测试 API → 确认数据获取正常
6. 更新 TODO 文件 → 标记 [x] 完成

```bash

### 5.3 常见问题处理

| 问题 | 处理方式 |

|------|----------|

| AKShare 接口返回英文字段 | Provider 中添加 `field_mapping` 或在 `fetch_data` 中重命名 |

| AKShare 接口有 bug | 在本地 AKShare 源码中修复，`git commit` 后 `pip install -e .` |

| 接口需要特殊参数处理 | 重写 Provider 的 `fetch_data` 方法 |

| 数据量过大 | 考虑分批获取，设置 `batch_size` 和 `delay` |

## 7. 开发经验总结

### 7.1 更新策略决策树

```bash
接口有参数吗？
├─ 否 → 仅批量更新（全量刷新）
└─ 是 → 参数类型？
    ├─ symbol/code → 单条 + 批量（从基础表获取代码列表）
    ├─ date（截面） → 单条 + 批量（遍历日期，默认 2010-01-01 至今）
    ├─ start_date + end_date → 增量更新（从最新日期续取）
    └─ 其他 → 分析参数含义，设计合理的批量策略

```bash

### 7.2 关键配置说明

- *Provider 必填属性**：

```python
collection_name = "xxx"           # 集合名（唯一标识）

display_name = "显示名称"          # 前端显示名

akshare_func = "xxx"              # AKShare 函数名

unique_keys = ["字段 1", "字段 2"]   # 去重键

field_info = [...]                # 字段定义（必须中文）

```bash

- *Service 批量更新配置**：

```python
batch_source_collection = "xxx"   # 代码列表来源集合

batch_source_field = "代码"        # 提取的字段名

batch_use_date = True             # 是否需要日期参数

batch_use_year = True             # 是否需要年份参数

batch_years_range = (2010, None)  # 年份范围

batch_concurrency = 3             # 并发数

```bash

### 7.3 字段命名规范

- **所有字段必须使用中文名**（与 AKShare 返回一致或做映射）
- 时间字段统一命名：`日期`、`时间`、`更新时间`
- 代码字段统一命名：`代码`、`股票代码`、`期货代码`、`期权代码`
